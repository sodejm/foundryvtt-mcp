Preserve get_journal as a summary with at most 500 Unicode code points per visible text page. Add stable journal/page IDs and verified UUIDs, sort order, type, source format, explicit contentTruncated flags, and bounded page-list continuation. Introduce get_journal_page for complete content retrieval. Both use immutable SnapshotPaginator records and the existing readMetadata contract. Default limit is four records and maximum eight, keeping both text and structured responses within 128 KiB.

get_journal_page accepts journalId, pageId, format (text or source, default text), limit, and cursor. Text mode converts HTML without executing it, preserving headings, paragraph and line breaks, entities and Unicode. Markdown is returned intact with its source format identified. Source mode returns the exact stored HTML or Markdown as inert strings. Each chunk has index, start, end, and content; offsets count Unicode code points. Chunks contain at most 1,024 code points. Empty text has one empty chunk. Non-text pages return typed metadata, safe bounded asset fields, and zero chunks. The response reports contentLength, complete, contentTruncated, pagination and freshness. Consumers concatenate chunk content in order.

Journal/page projection happens before content, metadata, assets, totals or cursors are built. Unknown or denied entries use the same unavailable error in delegated mode. Cursors bind to caller, user, world, session, authorization fingerprint, requested format, and a digest of visible journal/page content and ordering. Edits, reorders, deletions, ownership changes and reconnects invalidate continuation. Reject invalid IDs, unknown input keys, malformed/tampered/expired cursors, changed limits and unsupported capacity explicitly. Source input is capped at 4 MiB before parsing; oversized snapshots fail rather than silently lose content.
